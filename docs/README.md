## Documentation Principles

A good document should help someone take the next responsible step. We aim for documentation that is:

- **Specific:** describe real workflows and concrete commands.
- **Honest:** distinguish what is implemented, tested, planned, and uncertain.
- **Kind:** make room for first-time contributors and non-specialists.
- **Maintainable:** update the relevant guide when a workflow changes.

If a guide leaves you unsure what to do next, please open an issue or improve it in a pull request. That feedback is part of the product.
